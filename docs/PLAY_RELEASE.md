## 2. Versioning

`pubspec.yaml` carries `MAJOR.MINOR.PATCH+BUILD`:

- `versionName` = `MAJOR.MINOR.PATCH` (what users see).
- `versionCode` = `BUILD`; it **must increase for every upload** and can never be
  reused, including for rejected uploads.
- Tag every submitted build: `git tag -a v1.0.0 -m "1.0.0"`.

## 3. Signing

The release build is signed with an upload key. Both files are gitignored:

```
android/upload-keystore.jks   # the key — BACK THIS UP
android/key.properties        # its passwords — BACK THIS UP
```

The keystore was generated with a 10,000-day validity (certificate expires
2054-03-07), alias `upload`, CN `Techloft Attendance`. Losing these files means
requesting an upload-key reset from Google Play; losing them **after** the app
is published without Play App Signing re-enrolment can make updates impossible.

To use a different key:

```bash
keytool -genkeypair -v -keystore android/upload-keystore.jks \
  -storetype JKS -keyalg RSA -keysize 2048 -validity 10000 \
  -alias upload -dname "CN=Your App, O=Your Business, C=IN"
cp android/key.properties.example android/key.properties
# edit android/key.properties with the passwords you chose
```

Release builds **fail with a clear message** when `android/key.properties` is
missing — they never silently ship an unsigned or debug-signed bundle.

is declared optional (`android:required="false"`), so devices without a camera
can still install the app and use app-button attendance.

## 7. Reviewer instructions (App access)

Create dedicated reviewer accounts in the **production** Supabase project; do
not use real staff accounts. Suggested setup:

1. Owner: `review-owner@<publisher-domain>` signs up, creates a business
   ("Review Cafe"), sets timezone, and adds one employee. The invite token is
   shown once — give the employee account the token out of band.
2. Employee: `review-employee@<publisher-domain>` signs up and claims the token.
3. In Play Console → App access, provide both emails/passwords and these steps:
   - Sign in as the owner → dashboard, staff, report, attendance rules,
     workplaces, account screen.
   - Sign in as the employee → punch in with location permission granted.
   - Location note: a punch is accepted only inside the workplace geofence. The
     reviewer can set the workplace to their current position and use the
     maximum 500 m radius, or verify the rejection copy ("outside the permitted
     workplace area") without moving.
   - QR path: as the owner, open Workplaces → QR, display the code, then scan it
     from the employee account (QR attendance must be enabled in Attendance
     rules).
   - Account deletion: open Account → Delete account. Use a throwaway reviewer
     owner because deleting an owner deletes the business.

The full two-phone script (owner + employee, geofence, QR, corrections,
permissions, offline, deletion) is `docs/TESTER_GUIDE.md`. Reuse it for the
reviewer run and for internal testing.

## 9. Known limitations at submission time

- Map tiles use the public OpenStreetMap servers, which are pilot-only; the
  production tile contract is tracked in slice 9.
- QR scanning and the owner attendance-rules form have not yet been exercised
  on the Android device (slice 9).
- The owner dashboard refreshes on pull-to-refresh, not Realtime.
- A lost invite token cannot be re-issued yet without deleting the member.
- Corrections cover check-out times only; a check-in correction would change the
  stored lateness classification and is out of scope for 1.0.
- No crash reporting or analytics is configured, so the Data safety form
  declares no diagnostics. Add both together if that changes.
